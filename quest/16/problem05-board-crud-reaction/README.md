# 문제 5 — 게시글·댓글 CRUD와 반응 토글

> 2026년 6월 25일 수업 복습

오늘 완성한 `step17-board-backend`를 복제한 실행 가능한 베이스 코드입니다. 단순히 코드를
따라 쓰는 대신 API를 직접 호출하고, 권한과 데이터 무결성 문제를 찾아 개선하는 퀘스트입니다.

## 1단계: CRUD API 확인

다음 API를 `requests.http` 또는 Swagger에서 순서대로 테스트하세요.

1. 로그인 후 게시글 등록
2. 등록한 게시글 수정
3. 다른 회원 토큰으로 수정하여 `403` 확인
4. 등록한 게시글 삭제
5. 없는 번호를 삭제하여 `404` 확인
6. 댓글 등록·수정·삭제도 같은 순서로 확인

## 2단계: 반응 토글 확인

한 게시글에 다음 순서로 요청하고 DB 행과 응답 개수를 확인하세요.

```text
LIKE → LIKE → DISLIKE → LIKE
```

예상 동작:

| 요청 | DB 결과 |
|---|---|
| 첫 LIKE | LIKE INSERT |
| 두 번째 LIKE | 기존 반응 DELETE |
| DISLIKE | DISLIKE INSERT |
| LIKE | DISLIKE를 LIKE로 UPDATE |

댓글 반응도 같은 규칙으로 동작해야 합니다.

## 4단계: 리팩터링 과제

게시글과 댓글의 반응 처리 코드는 구조가 거의 같습니다.

```text
기존 반응 조회 → 없으면 추가 → 같으면 삭제 → 다르면 변경 → 개수 조회
```

두 구현에서 공통으로 유지해야 할 규칙이 무엇인지 정리하고, 중복을 줄일 수 있는 방법을
README에 적어보세요. 무리하게 하나의 Service로 합치기보다 공통 규칙을 메서드나 테스트로
표현하는 방법도 좋습니다.

## 완료 기준

- 본인 글·댓글만 수정하고 삭제할 수 있음
- 비로그인 쓰기 요청은 401
- 남의 데이터 변경 요청은 403
- 없는 대상은 404
- 같은 반응 재클릭 시 취소
- 반대 반응 클릭 시 UPDATE
- 중복 반응 행이 생성되지 않음
- 검색 페이징 개수가 실제 검색 결과와 일치

## 실행

```powershell
cd backend
.\gradlew.bat bootRun
```

먼저 `src/main/resources/board.sql`로 `new_board_db`를 준비해야 합니다.
