## 5. 설치 순서

1. **MySQL**에서 문제지의 `CREATE DATABASE` ~ 샘플 데이터 `INSERT`까지 먼저 실행
2. 위 구조로 새 프로젝트 생성 (또는 `car-crud-project` 폴더 복사 후 이름/패키지만 변경해도 무방 — 구조가 거의 동일)
3. `application.properties`에 DB 비밀번호 입력
4. `findAll()` (목록 조회, JOIN)부터 만들어 DB 연결 확인 → 등록 → 수정 → 삭제 → 검색 순으로 확장

## 6. StudentMapper.xml 핵심 (JOIN + 동적 검색)

```xml
<select id="findAll" resultType="student">
    SELECT s.*, d.dept_name AS deptName
    FROM student s
    JOIN department d ON s.dept_id = d.dept_id
</select>

<select id="search" resultType="student">
    SELECT s.*, d.dept_name AS deptName
    FROM student s
    JOIN department d ON s.dept_id = d.dept_id
    <where>
        <if test="keyword != null and keyword != ''">
            AND (s.student_name LIKE CONCAT('%', #{keyword}, '%')
                 OR d.dept_name LIKE CONCAT('%', #{keyword}, '%'))
        </if>
    </where>
    ORDER BY s.created_at DESC
</select>
```

## 7. Controller 기본 메서드

| 메서드 | HTTP | 경로 | 설명 |
|---|---|---|---|
| `list()` | GET | `/students` | 목록 + 검색 화면 (`keyword` 파라미터로 검색 통합) |
| `newForm()` | GET | `/students/new` | 등록 폼 화면 |
| `save()` | POST | `/students` | 등록 처리 |
| `show()` | GET | `/students/{id}` | 상세 조회 |
| `editForm()` | GET | `/students/{id}/edit` | 수정 폼 (기존 값 채워서) |
| `edit()` | POST | `/students/{id}/edit` | 수정 처리 |
| `delete()` | GET | `/students/{id}/delete` | 삭제 처리 |

> `list()`에 `@RequestParam(required=false) String keyword`를 받아 검색까지 한 메서드에서 처리하는 방식 권장 (`/search` 별도 분리 불필요)

## 10. Thymeleaf `th:` 속성 정리

### list.html (목록 + 검색)

| 속성 | 용도 |
|---|---|
| `th:each="student : ${students}"` | 리스트 반복 |
| `th:text="${student.studentName}"` | 텍스트 출력 |
| `th:text="${student.deptName}"` | JOIN된 학과명 출력 |
| `th:href="@{/students/{id}(id=${student.studentId})}"` | 상세/수정 링크 |
| `th:action="@{/students}"` | 검색 폼 GET 액션 |
| `th:value="${param.keyword}"` | 검색창에 입력값 유지 |
| `th:if="${students.isEmpty()}"` | 결과 없을 때 메시지 |

### form.html (등록)

| 속성 | 용도 |
|---|---|
| `th:object="${student}"` | 폼 바인딩 객체 지정 |
| `th:action="@{/students}"` | 등록 POST 경로 |
| `th:field="*{studentName}"` | input과 필드 자동 바인딩 |
| `th:field="*{deptId}"` + `<select>` | 학과 드롭다운 |
| `th:each="dept : ${departments}"` | select option 반복 |
| `th:value="${dept.deptId}"` | option value |
| `th:text="${dept.deptName}"` | option 텍스트 |
| `th:errors="*{studentName}"` | validation 에러 메시지 |
| `th:if="${#fields.hasErrors('studentName')}"` | 에러 있을 때만 표시 |

### edit.html (수정 — form.html과 거의 동일)

| 속성 | 용도 |
|---|---|
| `th:object="${student}"` | 기존 값이 이미 채워진 객체 |
| `th:action="@{/students/{id}/edit(id=${student.studentId})}"` | 수정 POST 경로 |
| `th:field="*{studentId}"` (hidden) | id 값 유지용 |

### detail.html (선택)

| 속성 | 용도 |
|---|---|
| `th:text="${student.studentNo}"` 등 | 필드별 출력 |
| `th:href="@{/students/{id}/delete(id=${student.studentId})}"` | 삭제 버튼 |
| `onclick="return confirm('삭제하시겠습니까?')"` | 삭제 확인 (th 속성은 아니지만 실무 필수) |

## 11. 빠뜨리기 쉬운 것

- `th:field`는 자동으로 `id`, `name`, `value`를 다 채워주므로 `id`/`name` 속성을 따로 쓸 필요 없음
- 날짜(`created_at`) 출력 시: `th:text="${#temporals.format(student.createdAt, 'yyyy-MM-dd')}"`
- 학과 드롭다운은 `list()`나 `newForm()`에서 `model.addObject("departments", departmentService.findAll())`을 반드시 같이 넘겨야 함
